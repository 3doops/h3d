# Протокол мост ⇄ клиент, версия 0

WebSocket, текстовые кадры, один JSON-объект на кадр, поле `t` — тип. Адрес по умолчанию
`ws://127.0.0.1:8765` (`bridge.py --host 0.0.0.0` для доступа из сети).

Координаты — клетки движка `[x, y, z]`, `z` 0 — поверхность, 1 — подземелье. Ось `y` идёт вниз (как на карте
игры). Позиция объекта в движке — его **правая нижняя** клетка (якорь); занятые клетки задаются масками 8×6
от якоря влево-вверх.

Номера: `terrain` — тип почвы движка (0 dirt, 1 sand, 2 grass, 3 snow, 4 swamp, 5 rough, 6 subterranean,
7 lava, 8 water, 9 rock; HotA: 10 highlands, 11 wasteland — сверить в ENGINE_API.md). `river` 0 нет, 1–4;
`road` 0 нет, 1–3. Ресурсы: `[wood, mercury, ore, sulfur, crystal, gems, gold]`.

## Сервер → клиент

```jsonc
{"t":"hello","proto":0,"source":"engine|mock","game":"HotA 1.x"}

// полный снимок; после него — state или повторный snapshot
{"t":"snapshot",
 "map":{"size":36,"levels":2,
        "terrain":[[...size*size...],[...]],      // по уровням, строки сверху вниз
        "terrain_frame":[[...],[...]],            // номер картинки тайла (для разнообразия)
        "river":[[...]], "road":[[...]],
        "tflags":[[...]]},                        // бит0 mirrorX, бит1 mirrorY, бит2 coast, бит3 blocked, бит4 visitable
 "fog":[[...]],                                   // для игрока me: 1 открыто, 0 скрыто
 "objects":[{"id":12,"type":79,"subtype":6,"def":"AVTgold0","x":10,"y":7,"z":0,
             "block":"0000ff...","visit":"000001...","owner":-1}],   // маски 48 бит hex, бит = 8*row+col от левого верхнего
 "heroes":[...hero], "towns":[...town], "players":[...player],
 "date":{"day":1,"week":1,"month":1}, "current":0, "me":0}

// изменения динамического состояния после команды/хода
{"t":"state","objects_changed":[...object],"objects_removed":[12],
 "heroes":[...], "towns":[...], "players":[...], "date":{...}, "current":0,
 "fog_open":[[x,y,z],...]}

hero   = {"id":5,"name":"Orrin","owner":0,"class":0,"portrait":0,"x":10,"y":8,"z":0,"dir":3,
          "mp":1500,"mp_max":1500,"mana":10,"level":1,"exp":0,"primary":[2,0,1,1],
          "army":[[creatureId,count] x7, -1 пусто],"visible":true}
town   = {"id":0,"name":"Ashwood","owner":0,"faction":0,"x":20,"y":15,"z":0,"fort":1,"capitol":false,
          "visiting":5,"garrison":[[c,n] x7]}
player = {"id":0,"color":"red","human":true,"alive":true,"res":[20,5,20,5,5,5,20000]}

{"t":"path","hero":5,"cells":[[x,y,z,cost],...],"reachable":3}   // ответ на path; reachable — сколько клеток
                                                                  // пройдёт сегодня
{"t":"event","kind":"hero_move","hero":5,"cells":[[x,y,z],...]}   // фактический пройденный путь
{"t":"event","kind":"battle","attacker":5,"defender":{"type":"monster","id":33},"winner":"attacker",
 "losses":{...}}
{"t":"event","kind":"turn","current":1}                            // смена игрока (ИИ ходит в движке)
{"t":"event","kind":"window","name":"townScreen","action":"closed"}// окно движка пропущено (клиент без окон)
{"t":"window_open|window_frame|window_close", ...}                 // окно движка у клиента (см. «Изменения», 1.9)
{"t":"phase","phase":"menu|adventure|exited", ...}                 // меню игры / карта приключений (см. «Изменения», 4.5)
{"t":"dialog","id":7,"text":"...","style":"ok|yesno|choose","options":[{"text":"...","icon":"..."}]}
{"t":"error","msg":"..."}
```

## Клиент → сервер

```jsonc
{"t":"get_snapshot"}
{"t":"path","hero":5,"to":[x,y,z]}          // путь считает движок
{"t":"cmd","cmd":"move_hero","hero":5,"to":[x,y,z]}
{"t":"cmd","cmd":"select_hero","hero":5}
{"t":"cmd","cmd":"end_turn"}
{"t":"dialog_answer","id":7,"answer":0}       // ok/yes = 0, no = 1, choose = индекс варианта
```

Правило: клиент ничего не считает сам. После `move_hero` он ждёт `event hero_move` и `state`, затем анимирует.

## Изменения протокола

Меняет тот, кому нужно, с записью здесь (дата, поле, причина); версия растёт при несовместимых изменениях.

- 2026-10-18, мост к движку (1.3–1.8), всё совместимо (только новые поля и типы; клиент игнорирует незнакомое):
  - `snapshot`: `source` (`engine|mock|replay`), `file`. `objects[]`: `trigger` `[x,y,z]` — клетка входа (там движок
    хранит данные объекта), `count` — монстры: число существ (у HotA своя таблица), кучи ресурсов: количество;
    `town` — номер города для объектов-городов; `underlay: 1` — объект рисуется как земля. `river` — `RiverSet & 7`.
  - `hero`: `boat`, `sleeping`. Пока герой — выбранный герой ходящего игрока, движок держит его вне города, поэтому
    `town.visiting` = -1, хотя герой стоит на клетке входа (ставится снова, когда ход переходит).
  - `town`: `x,y,z` — клетка входа (якорь объекта минус 2 по x); `garrison_hero`, `built` (hex, биты построек движка).
  - `player`: список всегда из 8 (индекс = цвет); `alive` = не выбыл и есть герои/города; `heroes` (id), `towns` (число).
  - `path`: добавлено `to`; `cost` — накопленная стоимость от героя (растёт и на следующих днях).
  - `dialog`: `engine_style` (1/2/5/6/7/10 — NormalDialog, `extended`, `levelup`), `pics` `[{type,sub,icon,text}]`
    (все картинки окна), `options[].pic` `[type,sub]`; для `levelup` ещё `hero`, `options[].skill/skill_level`;
    `cancel: true` — у выбора есть отмена (ответ -1). `auto: N` — клиента не было, движку уже ответили N (отвечать не
    нужно). `event dialog_closed {id, answer, auto}` — ответа не дождались (таймаут / клиент ушёл).
  - `event hero_move`: добавлено `owner`; чужие герои — только клетки, видимые игроку `me`.
  - `event battle`: `attacker_owner`, `at` (клетка боя); `defender` для монстров: `{type:"monster", army, at}`;
    `losses: {attacker:[[c,n]...], defender:[[c,n]...]}` (потери по отрядам). Чужие бои — только если клетка видна.
  - `event turn`: добавлено `date`. `event window`: `action` `closed` (окно пропущено), `opened+closed` (экран
    города открыт движком и закрыт мостом), `answered` (повышение уровня); `town`, `hero`, `ret`.
  - Новое `{"t":"cmd_done","cmd":"move_hero|select_hero|end_turn","result":{...}}` — команда выполнена движком
    (после её `event`/`state`); ошибки команд — `error` с полем `re` (исходное сообщение).
  - Отладка (клиенту не нужно): `{"t":"debug_shot","path":"..."}` → `{"t":"debug","what":"shot","path","ok"}` — кадр
    экрана движка в PNG; `{"t":"debug_queue"}` → `{"t":"debug","what":"queue","queue":{...}}`.
- 2026-10-18, клиент: уточнение масок (без изменений формата) — 12 hex-цифр = 48-битное число, бит `i = (v >> i) & 1`,
  `i = 8*row+col`, row 0..5 сверху, col 0..7 слева; якорь (x, y) — бит 47 (`800000000000`). Мост и мок совпадают.
- 2026-10-18, сквозные окна движка (PLAN 1.9), всё совместимо: клиент, который не объявил `caps`, получает прежнее
  поведение (окна пропускаются по старым правилам), незнакомые типы игнорирует.

  ```jsonc
  // сервер → клиент
  {"t":"hello", ..., "caps":["windows"]}           // мост умеет показывать окна движка (у мока caps нет)
  {"t":"window_open","name":"townScreen","w":800,"h":600,"depth":1,"kind":"manager|dialog","town":2}
       // окно движка открыто и ЖДЁТ игрока; name: townScreen, heroScreen, heroMeeting, recruit, tavern, marketplace,
       // kingdomOverview, combat, …, "hota:0x…" (окно HotA), "vt:0x…" (неизвестное); вложенные — depth 2, 3…
  {"t":"window_frame","fmt":"jpg","w":800,"h":600,"seq":17,"name":"townScreen","data":"<base64>"}
       // кадр экрана движка (весь экран 800×600), только при изменении, не чаще --fps (8) в секунду;
       // медленный клиент получает только самый свежий кадр
  {"t":"window_close","name":"townScreen","depth":1,"ret":30722}   // depth 1 — окон движка больше нет; затем state
  // клиент → сервер
  {"t":"hello","client":"godot","caps":["windows"]}  // «я показываю окна движка» (после hello сервера)
  {"t":"window_input","kind":"mouse","x":170,"y":265,"button":"left|right","action":"move|down|up|click",
   "shift":false,"ctrl":false,"alt":false}           // координаты движка 0..w-1, 0..h-1
  {"t":"window_input","kind":"key","key":"Esc","action":"down|up|press"}  // key: имя (a–z, 0–9, f1–f12, esc, enter,
       // tab, space, backspace, up/down/left/right, home/end/pageup/pagedown, insert/delete, shift/ctrl/alt, - = [ ] ; '
       // ` \ , . /, kp_plus/kp_minus/kp_multiply), число — виртуальный код Windows, или "scan": DIK-код
  {"t":"window_refresh"}                               // прислать текущий кадр, даже если он не менялся
  {"t":"cmd","cmd":"open_town","town":2}               // экран своего города (как Enter на выбранном городе)
  {"t":"cmd","cmd":"open_hero","hero":70}              // экран своего героя (как двойной клик по портрету)
  {"t":"cmd","cmd":"adv_key","key":"K"}                // горячая клавиша карты приключений: K обзор королевства,
       // Q журнал заданий, C книга заклинаний, D копать, … (открытое окно придёт как window_open)
  ```

  - Окна, которые идут клиенту (`caps: ["windows"]`): все `DoDialog`-окна, кроме `NormalDialog`/`extended_dialog`
    (они остаются диалогами `dialog`), повышения уровня (`dialog` `levelup`) и итога боя (закрывается OK, клиенту —
    `event battle`); экран города, встреча героев (герой шагнул на своего героя), бой с `bridge.py --battles manual`.
    Окна внутри открытого окна (рынок из города, сообщения о постройке…) рисует и закрывает сам движок.
  - Герой вошёл в свой город / на своего героя: `event hero_move`, `state`, затем `window_open`; `cmd_done` для
    `move_hero` (и `open_town`/`open_hero`) приходит, когда окно закрыто. После закрытия всегда `state` (ресурсы,
    армии, постройки). `adv_key`: `cmd_done` сразу после нажатия, окно — отдельным `window_open`.
  - `open_town`/`open_hero`/`adv_key` без объявленных `caps` — `error`. Обрыв связи: окно остаётся открытым в игре,
    при новом `hello` с `caps` мост снова шлёт `window_open` и кадр. `bridge.py --window-timeout N`: без клиента с
    окнами N секунд — мост нажимает в окне Esc.
  - Отладка: `debug_shot` с путём `*.jpg` пишет JPEG (иначе PNG); `{"t":"debug_eval","src":"..."}` — только с
    `bridge.py --debug`.
- 2026-10-18, главное меню игры через проброс (PLAN 4.5), всё совместимо: старый клиент получает лишний тип `phase`
  (игнорирует) и, если мост запущен с `--load` (как раньше), — тот же поток сообщений; с `--menu` до входа на карту
  он видит только `hello`/`phase`/`window_frame`.

  ```jsonc
  // сервер → клиент
  {"t":"hello", ..., "caps":["windows","phase"]}     // мост сообщает фазы игры
  {"t":"phase","phase":"menu","gen":1,"why":"left|game_over"}
       // карты приключений нет: главное меню, выбор сценария / загрузка / кампания, рекорды, титры, вступление сценария,
       // «Ходит красный» перед первым ходом… Весь экран движка идёт кадрами window_frame (name "menu", только изменения,
       // ≤ --fps), window_input клиента — в движок, как для окна. Диалоги и окна здесь рисует сам движок (в кадре).
       // get_snapshot в этой фазе отвечает `phase`, path/cmd — error.
  {"t":"phase","phase":"adventure","gen":2,"size":36,"levels":2,"me":0,"current":0,"file":"GODOT_TEST","humans":[0]}
       // движок вошёл на карту (новая игра, загрузка, «начать заново», следующий сценарий кампании); сразу за ним —
       // новый snapshot с "why":"adventure" (карта, игроки и т. д. другие; клиент строит мир заново). gen растёт на
       // каждый вход на карту.
  {"t":"phase","phase":"exited"}                    // игра закрыта (выход из меню игры или процесс умер); мост выходит
  {"t":"snapshot", ..., "why":"adventure|player"}  // player: hot-seat, ход другого человека — его вид (туман, me)
  {"t":"event","kind":"engine_message","caption":"...","text":"..."}   // MessageBox Windows от игры (никто его не
       // видит: агент отвечает OK и пересылает текст; обычно это аварийное завершение движка)
  // клиент → сервер
  {"t":"cmd","cmd":"system_menu"}       // системные опции карты (кнопка движка: загрузить / сохранить / начать заново /
       // главное меню / выход / настройки) — окно window_open "systemOptions"; cmd_done после его закрытия
  {"t":"cmd","cmd":"adventure_options"} // параметры приключения (обзор мира, головоломка, копать, сведения о сценарии)
  ```

  - При подключении: `hello`, затем `phase`; в фазе adventure ещё `snapshot` (как раньше), в фазе menu — кадры.
  - Переходы: карта → меню — после закрытия окон (`window_close`) и последнего `state`; меню → карта — `phase
    adventure` и `snapshot`. Загрузка другой игры из системных опций проходит через меню (экран загрузки — кадры).
  - Hot-seat: `me` — человек, чей сейчас ход (во время ходов ИИ — последний человек); при смене человека вместо `state`
    приходит `snapshot` с `"why":"player"`. Сообщения «Ходит …» и вступление для игрока — обычные `dialog`.
  - `--battles game` (по умолчанию с `--menu`): бой как в игре — при выключенной «Быстрой битве» (системные опции)
    экран боя идёт окном `combat`, при включённой — быстрый бой; окно итогов боя (`combatResults`) игрок закрывает сам.
    Без клиента с окнами — быстрый бой. `--battles auto|manual` — как раньше.
  - Сетевая игра (DirectPlay) в этой сборке недоступна: кнопки IPX / TCP/IP / модем / прямое соединение / онлайн
    отвечают сообщением движка (в кадре меню), hot-seat работает.
- 2026-10-18, видимая оригинальная игра — зеркало (PLAN 4.6, `bridge.py --visible`), всё совместимо (новые поля и
  значения; без `--visible` поток сообщений прежний, кроме двух новых полей `state`):

  ```jsonc
  // сервер → клиент
  {"t":"hello", ..., "caps":["windows","phase","mirror"], "visible":true}
       // окно h3hota.exe открыто на рабочем столе: игрок играет и в нём, и в клиенте (visible:false — окно скрыто)
  {"t":"state", ..., "selected":70, "why":"external"}
       // selected — герой, выбранный в движке (у ходящего игрока me; иначе -1), есть и в snapshot.
       // why — отчего пришёл state: move_hero | end_turn | open_town | open_hero | turn | window_open | window_close |
       //   external. external — изменение сделал игрок прямо в окне игры (ход, подбор, выбор героя, найм …):
       //   клиент применяет его как обычный state, не дёргая камеру
  {"t":"event","kind":"hero_move","hero":70,"owner":0,"cells":[[5,28,0],[4,28,0]],"external":true}
       // шаги героя, которого игрок повёл в окне игры; ходьба там анимирована, поэтому один ход может прийти
       // несколькими hero_move подряд
  {"t":"dialog","id":3,"native":true, ...}      // диалог показан в окне игры и ждёт там; ответить можно с любой стороны
  {"t":"event","kind":"dialog_closed","id":3,"answer":0,"by":"native|client","ret":30725}
       // на диалог ответили: native — в окне игры, client — клиент (dialog_answer); ret — dialogReturn движка
  {"t":"event","kind":"engine_message","caption":"...","text":"...","shown":true}   // MessageBox показан по-настоящему
  ```

  - Как ловятся изменения из окна игры: на игровом потоке (C-хук `GetEvent`, раз в 250 мс, только в ход своего
    игрока-человека, когда нет команды моста, окна, диалога и боя) считается дайджест состояния — клетки и списки
    объектов, туман, игроки, города, герои на карте (без цели маршрута), дата, текущий игрок. Отличие от дайджеста
    последнего отправленного состояния → накопленные шаги (`hero_move` с `external`) и `state` `why: external`.
    Ходы ИИ, окна и диалоги сообщают о себе как раньше (`turn`, `window_close`, `dialog_closed` + `state`).
  - Окна движка (экран героя, город, рынок, обзор королевства, системные опции, бой, повышение уровня, итог боя …)
    в видимом режиме всегда идут в окне игры как в оригинале и одновременно клиенту окнами `window_open/frame/close`
    (если он объявил `caps: ["windows"]`); закрыть / нажать можно с любой стороны. Диалоги `NormalDialog` /
    `extended_dialog` (сундук, «герои ещё могут ходить», сообщения дня/недели, события карты) — `dialog` с
    `native: true`: ответ клиента мост превращает в клики по кнопкам этого диалога в окне игры (подсказки правой
    кнопкой, пока она зажата в окне игры, клиенту не идут). Таймаута ответа нет,
    MessageBox Windows не отвечается автоматически. Фазы (`phase menu/adventure/exited`) — как раньше, откуда бы ни
    пришёл переход.
  - Очерёдность (оба играют сразу): всё выполняется на игровом потоке движка по очереди. Команда клиента (`path`,
    `move_hero`, `end_turn`, `open_town` …), пришедшая, когда в окне игры открыт диалог / окно / идёт бой или ход ИИ,
    ждёт в очереди моста и выполняется, когда карта приключений снова свободна (ответ — после этого; `error` по
    таймауту команды). Клики в окне игры во время команды клиента движок обрабатывает сам, как обычный ввод (клик
    по карте во время ходьбы героя её останавливает — как в оригинале). Ответ на диалог с обеих сторон: побеждает
    первый, второй игнорируется.
