# План: 3D-клиент на Godot поверх оригинальной HotA

Начат 2026-10-17. Идея и обоснование: `docs/ideas/godot-client-over-original-engine.md`.

**Цель прототипа:** запущенная оригинальная игра (SoD + HotA.dll) считает всю механику, Godot показывает
трёхмерный мир и шлёт команды игрока. Ни одного правила механики в клиенте: путь, очки хода, посещение объектов,
бой, ИИ — всё делает движок.

```
game\Heroes3_HotA1\h3hota*.exe  ── Frida-агент (bridge/*_agent.js, bridge_runtime.js): состояние, команды на потоке игры,
        │                          перехват NormalDialog
        │ frida messages
bridge/bridge.py  ── WebSocket ws://127.0.0.1:8765, JSON (PROTOCOL.md); --mock отдаёт записанный снимок
        │
client/ (Godot 4)  ── 3D-рельеф, 3D-объекты из assets3d, герои, путь, HUD, диалоги
```

## Решения

- **Мост v0 — Frida** (Python + JS-агент): правки без перезапуска игры, `frida` уже стоит. v1 — своя DLL на
  patcher_x86 (этап 5), протокол тот же.
- **Протокол** — JSON по WebSocket, описан в `PROTOCOL.md`. Клиент и мост делаются параллельно; клиент
  отлаживается на `bridge.py --mock`.
- **Бой в прототипе** — движок сам проводит бой (автобой за игрока), клиент показывает итог. 3D-бой — этап 5.
- **Окна движка, которые клиент ещё не умеет** (город, герой, рынок, обмен, бой…) — простые вопросы идут в клиент
  как диалог, остальные окна остаются открытыми в движке, и клиент показывает их кадром с вводом мыши/клавиш (1.9);
  клиент без этой возможности получает старое поведение (окно закрывается с записью в лог). Свои 3D-экраны — этап 5.
- **Графика.** 3D-модель для каждого типа объекта. Конвейер: текстовое описание объекта (составлено по
  оригинальному ассету: имя, класс, что изображено) → эскиз Codex image_gen со стилем по референсам пользователя
  (`ref/`) → TRELLIS.2 → Blender (масштаб под клетки, децимация, JPEG) → GLB → `manifest.json`. Спрайты игры на
  вход генерации не подаются (ограничение из docs/ideas). Чего ещё нет — процедурная заглушка по категории,
  поэтому на карте нет «дыр».
- **Стиль** (референсы `ref/`): реалистичная фэнтези-диорама, вид сверху под углом, снег/хвоя/скалы, тёплый
  закатный свет, мягкие тени; объекты читаются с высоты как в `ref1`/`ref2`, отдельная модель — как `ref3`.
- **Где видно пользователю:** агент работает в session 0 без рабочего стола. Проверка — скриншоты и видео
  Godot (Mesa llvmpipe, `--write-movie`). Пользователь открывает `client/` в своём Godot и подключается к мосту
  на ВМ (или через web-экспорт).
