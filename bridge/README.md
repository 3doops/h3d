# Мост к игре (`godot/bridge/`)

| Файл | Что |
|---|---|
| `bridge.py` | WebSocket-сервер (PROTOCOL.md): запускает игру (с главного меню `--menu` или сразу с сохранением `--load`) или подключается к ней, `--mock`, `--replay`, `--record` |
| `bridge_agent.js` | агент, часть 1: чтение состояния движка (снимок: клетки, туман, объекты, герои, города, игроки) |
| `bridge_runtime.js` | агент, часть 2: команды на игровом потоке, события, перехват диалогов, боёв и окон |
| `snapinfo.py` | разница состояний для `state`, таблица типов объектов `objects_*.tsv` |
| `test_client.py` | сквозной тест через WebSocket (две игры), кадры движка в `godot/out/bridge/` |
| `frames.py` | кадр движка (RGB565) → JPEG через GDI+ (ctypes, ~мс на кадр 800×600); запасные Pillow / PNG |
| `tools/pt_probe.py` | ручная проверка окон движка: команды, клики/клавиши в координатах движка, кадр в JPEG |
| `launch.py` | запуск игры без рабочего стола, авто-загрузка сохранения, сводка, снимок экрана движка |
| `game_agent.js` | Frida-агент: исправления для session 0, автоматизация меню, задания на игровом потоке, чтение состояния |
| `testdata/GODOT_TEST.GM1` | тестовое сохранение (копия `game\Heroes3_HotA1\games\GODOT_TEST.GM1`) |
| `testdata/GODOT_BATTLE.GM1` | второе сохранение для теста боя: «Too Many Monsters», рядом с героем стая фамильяров |
| `testdata/snapshot_newcomers.json` | настоящий снимок движка (GODOT_TEST, день 1) — для клиента и ассетов; `bridge.py --mock --replay` |
| `testdata/objects_newcomers.tsv` | типы объектов этой карты: класс, подтип, def, сколько, имя |
| `tools/h3m_scan.py` | обзор карт `.h3m` (размер, игроки, доля снега, разнообразие объектов) — по нему выбрана тестовая карта |
| `ENGINE_API.md` | адреса и структуры движка; [R] — проверено на живой игре, итоги — раздел 13 |
| `mock_server.py` | мок моста для клиента (ведёт агент клиента; `bridge.py --mock` его использует) |
| `doctor.py` | локальный режим: поиск папки игры, чек-лист «чего не хватает» с подсказками (Windows; Linux + Wine), команда запуска моста; `--json` для клиента |
| `test_doctor.py` | тесты `doctor.py`, в т. ч. имитация Linux (поддельные префиксы Wine, Lutris, Proton, ответы `wine`) |
| `requirements.txt` | модули Python моста: `frida>=17`, `websockets>=13` |

## Мост (`bridge.py`)

```
h3hota.exe ── Frida: game_agent.js + bridge_agent.js + bridge_runtime.js (один скрипт)
   │  send(): bridge (сообщение протокола) | state_raw (полное состояние) | cmd_done;  RPC: cmd, dialog_answer, снимок
bridge.py ── asyncio WebSocket ws://127.0.0.1:8765; state_raw → state (разница объектов и тумана)
   │
клиент (Godot) / test_client.py
```

Всё считает движок. Мост только передаёт:

- **Снимок** читается на игровом потоке (между двумя опросами ввода): клетки `NewfullMap`, туман `mapExtra`, живые
  объекты (все id в списках `ObjectCellList` клеток) с масками из `CObjectType`, владелец — `GetFlaggedObjectOwner`,
  число монстров — из таблицы HotA. После каждой команды и каждой смены игрока агент шлёт полное состояние, мост
  превращает его в `state` (`objects_changed/removed`, `fog_open`).
- **Команды** ставятся в очередь агента. Слушатель на `advManager::Main` (0x408710) берёт команду на холостом
  сообщении в ход человека, когда нет модальных окон: `path` — `ShowRoute` (как первый клик по карте, путь и
  «сегодня» из `pRouteArray`), `select_hero` — `SetHeroContext`; `move_hero` и `end_turn` подменяют холостое
  сообщение на нажатие кнопки `{0x200, 0xD, 7 | 0xC}`, и дальше `Main` сам делает то же, что при клике
  (ход, посещение, бой, напоминание «герои ещё могут ходить», `NextPlayer`). Ход ИИ идёт в движке сам; скорость:
  ходьба 4/4, `Delay` заменён — круг ИИ около секунды.
- **События:** `hero_move` — разница позиций после каждого шага `MoveHero` (и для ИИ, чужие — только видимые клетки),
  `turn` — `NextPlayer`, `battle` — `DoCombat` (победитель, потери по отрядам; бой человека — быстрый, им играет ИИ
  движка), `window` — окна, которые клиент ещё не рисует.
- **Диалоги:** `NormalDialog` и `extended_dialog` заменены: вопрос уходит клиенту, игровой поток ждёт
  `dialog_answer` (по умолчанию до 120 с, `--dialog-timeout`), ответ пишется в `dialogReturn`. Нет клиента или нет
  ответа — ответ по умолчанию (OK / да / левая картинка) и запись в лог; клиент видит такой диалог с `auto`.
- **Окна движка — сквозной показ (PLAN 1.9).** Клиент, приславший `{"t":"hello","caps":["windows"]}`, получает
  окна, которые сам не рисует: `DoDialog`-окна (экран героя, найм, рынок, таверна, университет, обзор королевства,
  окна HotA …), экран города и встречу героев (`CallManager` townManager / swapManager), бой при `--battles manual`
  (combatManager). Окно работает как в игре: игровой поток крутит свой модальный цикл, мост шлёт `window_open`,
  кадры `window_frame` (JPEG, только изменившиеся, ≤ `--fps` 8/с, медленному клиенту — последний) и `window_close`,
  а `window_input` клиента кладётся в очередь ввода движка в формате `CheckDown`/`CheckUp` (C-хук на
  `inputManager::GetEvent` отдаёт по одному сообщению, когда очередь движка пуста; `GetCursorPos` в это время
  возвращает виртуальную мышь). Внутренние окна (найм из города, сообщения) рисует и закрывает сам движок.
  После закрытия — `state`. Остаются родными: `NormalDialog`/`extended_dialog` → `dialog`, повышение уровня →
  `choose`, итог боя → OK. Без клиента с окнами — старые правила: повышение уровня → `choose`; итог боя → OK;
  остальные — пропуск с «отмена» и `event window`; экран города открывается (логика посещения) и сразу
  закрывается `{0x200, 10}`; встреча героев пропускается. `--windows name=policy,...` (`pass | run | ok | cancel`,
  `townScreen=close`, `heroMeeting=skip`, `*` — все прочие) меняет правило для окна.
- **Главное меню и фазы игры (PLAN 4.5).** `bridge.py --menu` запускает игру до её главного меню и ничего не
  выбирает сам: игрок видит меню кадрами и играет мышью/клавишами, как в оригинале — новая игра (сценарий, случайная
  карта, кампания, обучение, hot-seat), загрузка, рекорды, титры, выход. Агент следит за внешним циклом игры `oldmain`
  (0x4EEA70): карта приключений идёт ровно пока работает вызов `executive::MainLoop` (0x4B0BA0) из `oldmain`
  (вложенные циклы экрана города и боя идут из `CallManager`). Вход в этот вызов — `phase adventure` и снимок новой
  карты (читается тут же, на игровом потоке; кэш типов объектов и позиции героев сбрасываются), выход — `phase menu`
  («главное меню», загрузка из системных опций, «начать заново», победа/поражение, следующий сценарий кампании проходят
  через него и снова входят на карту). В фазе menu ввод клиента идёт в очередь движка тем же C-хуком, что и для окон, мост
  шлёт кадры всего экрана (`window_frame`, name `menu`); `NormalDialog`/`DoDialog`/`CallManager` и `Delay` работают как в
  игре (без перехвата). Вступление сценария и «Ходит красный» показываются ещё до цикла карты — то есть в фазе menu,
  кадром. Команда `system_menu` — кнопка «системные опции» карты (`ProcessDeSelect` 10 → `DoSystemOptions`), окно
  `systemOptions` идёт клиенту окном; `adventure_options` — кнопка 9. Hot-seat: `me` — человек, чей ход
  (`giCurWatchPlayer`, во время ИИ — последний человек), при смене человека в `NextPlayer` — новый снимок (`why: player`).
  Выход из игры: процесс завершился → `phase exited`, мост выходит (`status.json` `exited`).
- **Бои при `--menu`** (`--battles game`, по умолчанию с `--menu`): как в игре — решает опция «Быстрая битва»
  (системные опции; мост её не трогает и в реестре не меняет): выключена → экран боя окном `combat` (игрок сам жмёт
  «автобой» и т. п.), включена → быстрый бой; окно итогов боя закрывает игрок. Нет клиента с окнами — быстрый бой.
- **Сетевая игра недоступна:** DirectPlay в Windows не установлен и заглушён (см. «Как это работает»); кнопки IPX,
  TCP/IP, модем, прямое соединение и «онлайн» в окне «Несколько игроков» отвечают сообщением движка, hot-seat («Один
  компьютер») работает.
- **Видимая игра — зеркало (PLAN 4.6, `--visible`).** Окно h3hota.exe — обычное окно на рабочем столе (по умолчанию
  мост создаёт его без `WS_VISIBLE` и не даёт показать), играть можно и в нём, и в клиенте одновременно:
  - кадр: всё, что движок выводит на первичную поверхность DirectDraw (`Blt`/`BltFast`, курсор уже вложен),
    C-слушатель копирует через GDI (`GetDC` поверхности → `BitBlt` в клиентскую область окна) — 16-битный блит DDraw
    на 32-битный рабочий стол может не пройти; `IsIconic` окна игры всегда 0, чтобы свёрнутое окно не останавливало
    игру (`Process1WindowsMessage` ждал бы в `GetMessage`);
  - анимации — как в игре (свой `Delay`, скорость ходьбы игрока из реестра, звук игрока); окна движка (город, герой,
    рынок, бой, повышение уровня, итог боя, системные опции …) идут в окне игры и клиенту (`window_*`) — закрыть
    можно с любой стороны; `NormalDialog`/`extended_dialog` идут в окне игры родным циклом и клиенту `dialog` с
    `native: true`, ответ клиента — клики по кнопкам этого диалога (по id виджета в верхнем окне) через очередь
    ввода; итог — `event dialog_closed {by: native|client}`; таймаута ответа и автоответа MessageBox нет; подсказки
    правой кнопкой в окне игры (пока она зажата) остаются только там;
  - что игрок сделал в окне игры: C-хук `GetEvent` раз в 250 мс (в ход своего человека, без команды моста, окон,
    диалогов и боя) зовёт `mirrorTick` на игровом потоке — дайджест (FNV) клеток и списков объектов, тумана, игроков,
    городов, героев (без цели маршрута), даты, текущего игрока; отличие → `hero_move` с `external: true` и `state`
    `why: external` (в `state` есть `selected` — выбранный герой движка); фазы меню/карты/выхода — как раньше;
  - мышь: `GetCursorPos` отдаёт виртуальную мышь клиента, только пока последней действовала она; настоящая мышь
    (движение по окну или любое сообщение мыши окна — хук `CheckDown` 0x4EC370) возвращает настоящую позицию. Нет
    курсора вовсе (session 0) — позиция последнего сообщения мыши окна, поэтому сообщения, посланные окну, работают
    как настоящий ввод (так тест имитирует игрока);
  - очерёдность: команды клиента ждут в очереди, пока карта свободна (нет окна/диалога/боя/хода ИИ), — см.
    PROTOCOL.md; ответ на диалог — кто первый.
  `--visible` нужен рабочий стол: в session 0 этой ВМ окно «видимо» только по стилю (`IsWindowVisible` = 0, `BitBlt`
  в окно не проходит — станция окон невидима), под Wine — любой X11/Wayland. С `--attach` меняется только поведение
  моста (окно и вывод — какими их сделал прежний запуск).
- **Команды окон:** `open_town` — `SetTownContext` + кнопка `{0x200, 0xD, 7}` с подменой `advCommand` 7 → 3
  (`town::View`, как Enter на выбранном городе); `open_hero` — `advCommand` 2 (`H3Hero::ShowDialog`); `adv_key` —
  нажатие клавиши в очереди ввода карты приключений (K обзор королевства и т. п.).

```
python -I godot/bridge/bridge.py                     # запустить игру (GODOT_TEST.GM1) и мост на 127.0.0.1:8765
python -I godot/bridge/bridge.py --menu              # игра с главного меню: игрок сам выбирает режим (бои: --battles game)
python -I godot/bridge/bridge.py --host 0.0.0.0      # доступ из сети
python -I godot/bridge/bridge.py --attach            # к уже запущенной игре (launch.py --keep)
python -I godot/bridge/bridge.py --load GODOT_BATTLE.GM1 --record godot/out/rec   # другое сохранение, запись трафика
python -I godot/bridge/bridge.py --battles manual    # бои человека на экране боя движка (окно у клиента)
python -I godot/bridge/bridge.py --menu --visible    # окно игры на рабочем столе: играть в нём и в клиенте (PLAN 4.6)
python -I godot/bridge/bridge.py --fps 8 --jpeg-quality 80 --window-timeout 0     # кадры окон (по умолчанию)
python -I godot/bridge/bridge.py --debug             # принимать debug_eval (JS в агенте; не с --host 0.0.0.0)
python -I godot/bridge/bridge.py --mock              # без игры: синтетическая карта mock_server.py
python -I godot/bridge/bridge.py --mock --replay godot/bridge/testdata/snapshot_newcomers.json   # записанный снимок
python -I godot/bridge/bridge.py --snapshot-only godot/bridge/testdata/snapshot_newcomers.json   # снять снимок + tsv
python -I godot/bridge/bridge.py --game-dir "D:/Games/HoMM 3 Complete"   # другая папка игры (или env HOTA_GAME_DIR)
```

### Локальный режим (мост запускает клиент)

Клиент (`client/scripts/local_mode.gd`) сам запускает мост на машине игрока — команду даёт `doctor.py --json`
(подробно: `godot/README.md`, раздел 0). По умолчанию — `--menu` (игра с главного меню); `doctor.py --load X.GM1`
или `load` в `user://local.cfg` — сразу это сохранение:

```
python -I bridge.py --game-dir DIR --port 8765 --menu --control-dir CTL --log CTL/bridge.log  # Windows
WINEPREFIX=… wine C:/…/python.exe -I Z:\…\bridge.py --game-dir C:\… --control-dir Z:\… …     # Linux (Wine)
python -I doctor.py [--game-dir DIR] [--json] [--find]     # чек-лист / список найденных папок игры
```

`--control-dir CTL`: мост пишет `CTL/status.json` (`state`: `starting` → `game` → `ready` | `error` | `exited`, `pid`,
`game_pid` сразу после spawn, `url`, `error`), выходит, когда появился `CTL/stop` (до готовности — сразу убивает свою игру,
после — обычный выход), или когда `CTL/heartbeat` старше `--heartbeat-timeout` (900 с; клиент обновляет его раз в 5 с).
Файлы, а не сигналы/pid — одинаково работает и для Windows-процесса, и под Wine. `--log FILE` — stdout/stderr в файл.
`--start-timeout` (180 с) — на каждую фазу запуска игры: клиент на программном рендере, стартуя одновременно, отнимает
у игры процессор. Настройки игры в реестре (`set_registry`) мост ставит на время работы и возвращает прежние при
выходе (`restore_registry`); без прав администратора пишет в `HKCU\Software\Classes\VirtualStore\MACHINE\…`
(у `h3hota.exe` нет UAC-манифеста, Windows виртуализирует его чтение HKLM; на ПК без прав администратора не проверялось).

Сохранения из `testdata\` мост сам копирует в `game\Heroes3_HotA1\games\`, если их там нет. Расширения протокола
(поля, `cmd_done`, `debug_shot`, `debug_queue`, окна `window_*`, `open_town`/`open_hero`/`adv_key`) записаны в
PROTOCOL.md, раздел «Изменения протокола». WebSocket: `ping_interval` 60 с, `ping_timeout` 600 с — клиент на
программном рендере может молчать минутами, пока строит мир.

### Тест

```
python -I godot/bridge/test_client.py      # ~2 мин: две игры, отчёт godot/out/bridge/test_report.json
python -I godot/bridge/test_client.py --only-battle    # только вторая игра (ручной бой)
python -I godot/bridge/test_client.py --scenario menu  # ~1 мин: главное меню → новая игра → меню → загрузка → выход
python -I godot/bridge/test_client.py --scenario mirror  # ~1,5 мин: --visible, ввод в окно игры + клиент (PLAN 4.6)
python -I godot/bridge/tools/pt_probe.py --do "cmd:open_town:2" --do "click:170,265" --out godot/out/pt/x.jpg   # ручная проверка
```

Тест объявляет `caps: ["windows"]` и играет окна движка кликами в координатах 800×600 (найдены по кадрам).
1. hello + snapshot; 2. путь движка к ближайшей куче ресурсов, ход, ресурсы выросли, объект исчез; 3. сундук: диалог
`choose` (золото/опыт), ответ «опыт» → +1000 опыта → повышение уровня (диалог выбора навыка, ответ); 4. герой входит
в свой город → `window_open townScreen`, кадры; клик по жилищу скелетов (170,265) → окно найма, «макс.» (309,345),
«нанять» (387,345), выход (771,563) → `window_close` и `state`: −720 золота, +12 скелетов в гарнизоне; `open_hero` →
экран героя, Esc закрывает; `adv_key K` → обзор королевства, кнопка OK закрывает; 5. конец хода: «герои ещё могут
ходить?» → да, ходят три ИИ, снова красный, день 2; 6. вторая игра GODOT_BATTLE.GM1, `--battles manual`: атака стаи →
экран боя у клиента, клик по «автобой» (167,577) в ход игрока → движок доигрывает бой → итог закрыт OK, `event
battle`, монстр убран. Кадры движка: `godot/out/bridge/01_start.jpg … 07_battle_after.jpg` (debug_shot),
`08_town_window.jpg … 14_battle_autocombat.jpg` (window_frame), трафик `test_traffic*.jsonl` (без пикселей),
журналы моста `bridge_log_*.txt`.

Сценарий `--scenario menu` (мост с `--menu`, отчёт `test_report_menu.json`, журнал `test_log_menu.txt`, кадры
`20…29_menu_*.jpg`): главное меню кадрами → «Новая игра» → «Один игрок» → список сценариев → размер S → «Вновь
прибывшие» → «Начать» → вступление (ещё фаза menu) закрывается Enter → `phase adventure` + снимок новой карты 36×36×2,
путь движка на ней → `system_menu` (окно `systemOptions`) → «Главное меню» → подтверждение → `phase menu` → «Загрузить
игру» → «Один игрок» → первое сохранение (GODOT_TEST.GM1) → `phase adventure` + снимок (1233 объекта) → `system_menu`
→ «Выход из игры» → подтверждение → `phase exited`. Вручную проверены ещё: загрузка другой игры из системных опций
карты, бой с выключенной «Быстрой битвой» (экран боя, «автобой», итоги), hot-seat на двоих (снимок с `me` 3 после хода
красного), кнопка TCP/IP (сообщение движка, игра работает дальше). Кадры: `godot/out/menu/p*.jpg`.

### Известные ограничения

- На «The Newcomers» стартовые области закрыты стражами границы и охраняемыми проходами: ни один монстр в первые дни
  недостижим, поэтому бой проверяется на второй игре.
- Окна движка у клиента — картинка 800×600 и клики, без своего 3D-интерфейса (это этап 5). Клик или клавиша,
  пришедшие, пока движок проигрывает анимацию или ход врага в бою, движок отбрасывает (как настоящий клик); курсор
  движка (меч, стрелка) в кадр не попадает — клиент показывает свой.
- Без клиента с `caps: ["windows"]` окна пропускаются по старым правилам (вербовка, рынок … — «отмена»; встреча
  героев — без обмена). Встреча героев в сквозном режиме сделана, но тестом не проверена (на тестовых картах герои
  далеко друг от друга).
- Картинки диалогов описаны текстом (`pics`/`options`): имена навыков, артефактов, заклинаний, существ — из таблиц
  движка; у HotA-заголовков текст начинается с `{Заголовок}`.
- `town.visiting` = -1, пока герой выбран в свой ход (так держит движок); позиция героя — клетка входа города.
- Ход ИИ не прерывается: команды клиента во время хода ИИ ждут в очереди до хода человека.
- Почвы HotA 10/11 и старшие биты рек не проверены (их нет на тестовых картах); мост шлёт `RiverSet & 7`.
- Фаза menu: вступление сценария и «Ходит …» в начале игры — кадр меню поверх ещё не показанной 3D-карты (так их
  показывает движок до своего цикла карты). Hot-seat: между ходами людей клиент не прячет карту предыдущего игрока
  (оригинал закрывает её сообщением «Ходит …» — оно приходит клиенту диалогом).
- Сетевая игра (DirectPlay) недоступна; для неё нужен настоящий DirectPlay и рабочий стол.
- Агент на Frida: команды и диалоги идут через JS; при обрыве `bridge.py` игра продолжает работать без хуков моста.

## Запуск игры

Оригинальная игра — `game\Heroes3_HotA1\h3hota.exe` (SoD + HotA.dll 1.8.0, **без HD-мода**) — запускается
скрыто в session 0 через `frida.spawn`, агент ставится до старта. Через ~9 с загружена карта приключений.

```
python -I godot/bridge/launch.py              # загрузить GODOT_TEST.GM1, сводка, out/launch.png, закрыть игру
python -I godot/bridge/launch.py --keep       # то же, игра остаётся работать (Ctrl+C или --kill)
python -I godot/bridge/launch.py --load X.GM1 # другое сохранение из games\
python -I godot/bridge/launch.py --new "The Newcomers.h3m" --save GODOT_TEST   # новая игра → сохранить → testdata\
python -I godot/bridge/launch.py --menu --keep   # остановиться в главном меню
python -I godot/bridge/launch.py --json out/s.json   # сводка в JSON
python -I godot/bridge/launch.py --kill       # убить все h3hota.exe
```

Python: `C:\Users\dev0\AppData\Local\Programs\Python\Python312\python.exe` (там стоит `frida` 17).
Папка игры: `--game-dir DIR` (`launch.set_game_dir`) > env `HOTA_GAME_DIR` > `game\Heroes3_HotA1` репозитория.
Одновременно — одна игра: перед запуском `--kill`, если что-то осталось.

Из кода:

```python
from launch import Game
g = Game.start()                    # spawn → меню → загрузка → ждёт фазу 'adventure' (иначе исключение)
g.api.state(); g.api.players(); g.api.heroes(); g.api.terrain_stats(); g.shot('x.png')
g.save('NAME')                      # game::SaveGame на игровом потоке → games\NAME.GM1
s = g.session.create_script(src); s.load()   # свой агент в ту же сессию
g = Game.attach()                   # к уже запущенной игре (например, launch.py --keep): только RPC, без стартовых хуков
```

RPC агента (`g.api.*`): `state()` (фаза `main-menu|select-scenario|adventure|adventure-dialog|combat`, менеджеры,
окна, дата, размер карты), `players()`, `heroes(all)`, `terrain_stats()`, `addresses()`, `shot()`,
`click(x, y)` и `key(scan)` (через очередь ввода движка, экран 800×600), `save(name)` → id задания, `job(id)`,
`idle_polls(n)`, `configure({...})`, `log()`.

### Как это работает

Стартовые исправления (`installStartupHooks`, только при spawn):

1. `CreateDPlayObject` @0x5559A0 → 0. DirectPlay в Windows не установлен; `CoCreateInstance(CLSID_DirectPlay)`
   из `CDPlayLobby::Init` @0x4985D0 виснет навсегда (скрытый запрос «установить компонент»). Поэтому же
   `CoCreateInstance` для CLSID DirectPlay/DirectPlayLobby сразу отвечает `REGDB_E_CLASSNOTREG`, а сетевые кнопки окна
   «Несколько игроков» (`TMultiPlayerWindow::OnWidgetDeselect` @0x50F740, пункты 0x65, 0x67–0x6A) показывают сообщение
   движка: иначе `InitConnection` @0x555AD0 без объекта DirectPlay вызывает `ShutDown("DirectPlay Error")`.
   `MessageBoxA/W` (в session 0 его никто не видит, игра висела бы на нём) — в лог и сразу OK; мост пересылает текст
   клиентам (`event engine_message`).
2. `GetDeviceCaps(BITSPIXEL)` → 16 для exe и `gConfig.FullScreen = 0` перед `InitDirectDraw` @0x601AB0. Иначе движок
   (рабочий стол не 16 бит) уходит в полный экран, а `SetDisplayMode(800,600,16)` в session 0 даёт `DDERR_UNSUPPORTED`.
3. DirectDraw: внеэкранные поверхности создаются как RGB565, `GetPixelFormat` всегда отвечает RGB565, неудачные
   `Blt/BltFast/Flip` на 32-битную первичную поверхность считаются успешными. Логика рисует в
   `gpWindowManager->screenBitmap` (+0x40: 800×600, pitch 1600) — это и есть снимок экрана (`shot`, PNG без PIL).
4. Реестр `HKLM\SOFTWARE\WOW6432Node\New World Computing\Heroes of Might and Magic® III\1.0` (его читает только
   этот exe; HD держит настройки в `_HD3_Data\Settings\hota.ini`, их не трогаем): окно, без заставки и звука,
   `Autosave=0` (не перезаписывать AUTOSAVE.GM1 пользователя), `Quick Combat=1`.

Автоматизация: `TMainMenu::DoModal` @0x4FBD70 и `TGameTypeWindow::DoModal` @0x4D5B20 сразу возвращают выбор
(0x66 «загрузить» / 0x65 «новая», 100 «одиночная»); `FindFirstFileA/FindNextFileA` для `*.gm?` / `*.h3m` отдают
только нужный файл — в настоящем окне выбора сценария одна строка, и она выбрана; клик по «Загрузить/Начать»
(495,553) кладётся прямо в кольцевую очередь `inputManager` (+0x38, 64×0x20). Дальше движок сам грузит игру своим
обычным путём (`BeginSavedGame` → `game::LoadGame`). Для новой игры вступительное сообщение закрывается Enter.

Задания на игровом потоке: C-хук (CModule) на `inputManager::GetEvent` @0x4EC660 вызывает JS только когда есть
задание (сохранение и т. п.). Тот же хук после 16 пустых опросов подряд спит 1 мс: exe без HD крутит цикл
вхолостую (75% ядра → ~10%). Включается после загрузки карты, `idle_polls(0)` выключает.

### Проверенные адреса (HotA 1.8.0, h3hota.exe)

- `gpGame` 0x699538: дата +0x1F63E/40/42 (день/неделя/месяц), карта +0x1FB70 (`NewfullMap`: Size +0xD4,
  HasTwoLevels +0xD8, cellData +0xD0, клетка 0x26, почва +4), игроки +0x20AD0 × 0x168 (герои +8, ресурсы +0x9C,
  isLocal +0xE1, isHuman +0xE2), `playerDead` +0x1F636, имя файла +0x1F4D5.
- Герои: HotA выносит массив (215 героев, 0x492 байта) из `game`; база = `*gpGame + [0x402480]`.
  **Смещение в 0x402480 HotA вычисляет при запуске, оно разное в каждом запуске** (0x60FFB8…0x74FFB8; в снимке
  `analysis/runtime` было 0x6140000), читать его каждый раз. Число героев — imm в 0x4BB1EE (215).
- `gpExec` 0x699550 → список менеджеров (`advManager` появляется на карте), `gpWindowManager` 0x6992D0:
  headWindow +0x58 = верхнее окно (vtable 0x63A5E4 карта, 0x63DB40 диалог, 0x641CBC выбор сценария).
- `game::SaveGame` @0x4BEB60 `(gpGame, name, 1, 1, 1, 0)` → `games\name.GM1`.

### Что не сработало и почему

- `schtasks /IT` в session 1 — с 2026-10-16 процессы там замирают; не нужен: session 0 хватает.
- Полноэкранный режим (настройка по умолчанию и любой рабочий стол не 16 бит) — `DDERR_UNSUPPORTED`
  (WINGRAPH.CPP:164) → окно «Unexpected Program Termination» и висение.
- Блокировка только `CoCreateInstance` DirectPlay — падение позже в `FUN_004986E0` (объект лобби создан
  наполовину); поэтому заглушена вся `CreateDPlayObject`.
- Без формата 565 внеэкранная поверхность 32-битная (pitch 3200): игра пишет 16-битные пиксели — логика
  работает, картинка мусор.
- Предвыбор файла через `gMapName` — HotA его не использует (выбирает последний/первый в своём порядке),
  поэтому фильтр списка файлов.
- `h3hota HD.exe` виснет на том же DirectPlay; с заглушкой доходит до меню (экран 1920×1080×32 по `hota.ini`
  пользователя). Не используем: HD меняет экранные константы движка (800/600 → 1920/1080) и добавляет тысячи
  своих хуков, а его настройки — это `hota.ini` пользователя.

Остановить: `launch.py --kill` (или `taskkill /F /IM h3hota.exe`). Если процесс `launch.py` убит, игра
продолжает работать без его хуков (проверено), к ней можно подключиться `Game.attach()`.
