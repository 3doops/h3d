# Godot-клиент (`godot/client/`)

3D-клиент поверх оригинальной HotA: мост (`godot/bridge/`) отдаёт по WebSocket состояние движка
(`godot/PROTOCOL.md`), клиент рисует мир и шлёт команды. Механики в клиенте нет: путь, ход, посещения, бои,
диалоги — всё от движка (или от мока). Godot 4.7 (Forward+), только GDScript.

## Запуск

```
# мост к игре (запускает h3hota.exe скрыто, карта The Newcomers):
python -I godot/bridge/bridge.py
# или без игры — мок: синтетическая карта 48×48 / записанный настоящий снимок с мок-механикой
uv run --with websockets python godot/bridge/mock_server.py [--reveal] [--replay godot/bridge/testdata/snapshot_newcomers.json]

# клиент: открыть godot/client/ в Godot 4.7 и запустить (F5), или из консоли
Godot_v4.7.2-stable_win64.exe --path godot/client -- --server ws://127.0.0.1:8765
```

Скриншоты и видео без рабочего стола (session 0, без GPU): `bash godot/tools/shot.sh` — сам поднимает мок, кладёт
результат в `godot/out/`. Рисует Forward+ на Mesa lavapipe (Vulkan): `_dl/godot/lvp/` = `Godot_lvp.exe` +
`vulkan_lvp.dll` + `vulkan-1.dll` (переходник `godot/tools/vkshim/vulkan-1.def`: системный загрузчик Vulkan
игнорирует `VK_DRIVER_FILES` в повышенной сессии). Запасной путь — D3D12 WARP (`-d`). Один кадр 1600×900 на CPU —
секунды; первый кадр долго компилирует шейдеры (1–5 мин).

```
bash godot/tools/shot.sh -o overview -r -- --cam 18,16 --dist 22      # кадр мока без тумана
bash godot/tools/shot.sh -o real -r -R godot/bridge/testdata/snapshot_newcomers.json   # настоящая карта
bash godot/tools/shot.sh -o demo -a -v 40 -s 1280x720                  # видео авто-сценария (mp4, ffmpeg)
bash godot/tools/shot.sh -n -o engine -a -- --auto-shots out/real/auto  # против настоящего моста (уже запущен)
bash godot/tools/check.sh                                              # проверка синтаксиса всех скриптов
bash godot/tools/e2e.sh main [-v 20]                                   # сквозной прогон с игрой (+ видео) -> godot/out/final
bash godot/tools/e2e.sh battle                                         # ручной бой на GODOT_BATTLE.GM1
```

## Флаги клиента (после `--`)

| Флаг | Что |
|---|---|
| `--server URL` | адрес моста, по умолчанию `ws://127.0.0.1:8765` (локальный режим тогда выключен) |
| `--url URL` | то же, можно без `--` (панель адреса, `connect_panel.gd`) |
| `--local`, `--game-dir DIR`, `--local-port N` | локальный режим: клиент сам запускает игру + мост (`local_mode.gd`, `godot/README.md` раздел 0) |
| `--local-shot PNG` [`--local-shot-dialog`] | отладка: кадр панели локального режима после проверки (с открытым выбором папки) и выход |
| `--game-window on\|off\|auto` | локальный режим: окно оригинальной игры на рабочем столе (мост `--visible`, PLAN 4.6); `auto` — если есть рабочий стол; то же — галка «Окно игры на экране» в панели F3 |
| `--shot FILE --after SEC` | сохранить кадр через SEC секунд после построения мира и выйти |
| `--shots "5:a.png,9:b.png"` | несколько кадров |
| `--size WxH` | размер рендера для кадров/видео (по умолчанию 1600×900, не зависит от окна) |
| `--auto` | авто-сценарий: каждый свой герой — путь к ближайшей куче/сундуку → ход → ответ на диалоги кликом по кнопке → длинный путь (красный хвост); затем `--auto-wdemo`; конец хода → ходы ИИ → свой ход |
| `--auto-target CATS` | к чему идти: категории через запятую (по умолчанию `resource,chest,artifact,campfire`; `monster` — бой); цель — клетка входа объекта |
| `--auto-wdemo SPEC` | шаги окон движка после героев, синтаксис `--wdemo` (напр. город кнопкой HUD и найм кликами) |
| `--auto-no-far` / `--auto-no-end-turn` | без длинного пути / без конца хода (сценарий боя) |
| `--auto-shots PREFIX` [`--auto-ext jpg`] / `--auto-exit SEC` | кадры на каждом шаге сценария / выход после него |
| `--auto-report FILE` | отчёт JSON: проверки по шагам (путь, ресурсы, диалоги, окна, найм, бой, новый день) и хронология сообщений моста |
| `--exit-after SEC` | выйти через SEC секунд (для `--write-movie`) |
| `--cam X,Y` `--yaw` `--pitch` `--dist` `--level Z` `--hero ID` | начальная камера, уровень, выбранный герой |
| `--sun-az` `--sun-el` | направление солнца (градусы) |
| `--no-ui`, `--fast` (без SSAO), `--fps-log`, `--keep` | |
| `--overlay-live` | под окном движка мир продолжает рисоваться (по умолчанию — застывший затемнённый кадр, 3D выключено) |
| `--wdemo "town:2;frame;wait:3;shot:a.jpg;click:170,265;…;quit"` | сценарий окна движка для кадров без рабочего стола: `town:ID`/`hero:ID` (команда), `hudtown:ID`/`hudhero:ID` (клик по кнопке в HUD), `open` (ждать окно, которое открыла сама игра, напр. бой), `select:HERO`, `frame` (новый кадр), `wait:S`, `click:X,Y`/`rclick:X,Y` (координаты движка, настоящими событиями мыши через оверлей), `click_close:X,Y` (клик, пока окно не закроется, до 4 раз), `key:Escape`, `close`, `shot:PATH` (`.jpg` → JPEG), `quit`; отладка: `fake:S` (оверлей без моста), `fps:S` (время кадров) |
| `--menu-demo SPEC` | то же для экрана меню игры (мост `--menu`, PLAN 4.5): запускается при первом `phase menu`; ещё шаги `inphase:menu\|adventure` (ждать фазу), `phase:NAME` (следующий переход), `clickuntil:PHASE:X,Y` (клик раз в 5 с до фазы), `world:S` (ждать 3D-мир), `sysmenu` (клик по кнопке «Меню игры»), `check:menu\|world\|sysmenu\|back` (проверки для `--auto-report`); пример — `tools/e2e.sh menu` |
| `--quit-on-exit` | закрыть клиент через 3 с после `phase exited` и без локального режима (в локальном — всегда) |

Видео — штатный `--write-movie out.avi --fixed-fps 25` Godot (до `--`), `shot.sh -v` перекодирует в mp4.

## Управление

ЛКМ по клетке — путь от движка (зелёный — дойдёт сегодня, красный — позже), повторный клик — идти; ЛКМ по своему
герою или кнопка в списке — выбор. ПКМ-тащить — поворот, СКМ-тащить / WASD / стрелки — сдвиг, колесо / Z X —
масштаб, Q E — поворот, R F — наклон. Tab / PgUp / PgDn — поверхность/подземелье, Пробел — к герою, G — сетка,
Enter — конец хода (или OK в диалоге), Esc — сбросить путь, H — скрыть HUD, F2 — адрес удалённого моста, F3 — локальная
игра (чек-лист, папка игры, перезапуск).

**Окна игры (PLAN 1.9).** Город, экран героя, найм, рынок, таверна, обмен героев, окна HotA, бой (`bridge.py --battles
manual`) показывает сам движок: мост присылает кадр, клиент рисует его поверх затемнённого мира в рамке HUD
(по центру, с сохранением пропорций), мышь и клавиши над кадром уходят в игру (координаты 800×600), окно закрывает
игра (кнопкой в окне, Esc или ✕ в заголовке = Esc). Открыть: кнопка с башенкой у города в списке «Города», кнопка со
шлемом у героя в списке «Герои» (активны в свой ход, если мост объявил `caps: ["windows"]`; у мока их нет), или
войти героем в свой город / на своего героя. Пока окно открыто, камера и горячие клавиши карты выключены (F2 —
панель подключения — работает).

```
# проверка на настоящей игре без рабочего стола (мост уже запущен): открыть город, нанять скелетов кликами, выйти
bash godot/tools/shot.sh -n -o pt_client -t 1 -s 1280x720 -- --keep --fast --wdemo   "town:2;frame;wait:4;shot:$PWD/godot/out/pt/client_town.jpg;click:170,265;frame;wait:4;click:309,345;wait:2;click:387,345;wait:4;shot:$PWD/godot/out/pt/client_recruited.jpg;click:771,563;close;quit"
```

Кадры такой проверки — `godot/out/pt/client_town.jpg`, `client_recruit.jpg`, `client_recruited.jpg`, `client_after.jpg`.
На этой ВМ (lavapipe) мир рисуется ~2,7 с на кадр; пока окно открыто, 3D-проход выключен и окно отзывчиво, возврат к
миру — один долгий кадр (~8 с). Godot ограничивает `delta` при медленных кадрах, поэтому `wait:S` в сценарии на
открытом мире длится дольше S секунд.

## Устройство

| Файл | Что |
|---|---|
| `main.tscn`, `scripts/main.gd` | сборка сцены, флаги, атмосфера (солнце, тени, небо, туман, SSAO, glow), обработка протокола, ввод, кадры, `--auto` |
| `scripts/net.gd` | WebSocketPeer: JSON-кадры, переподключение с нарастающей паузой, статус, `reconnect(url)` |
| `scripts/connect_panel.gd` | автозагрузка `ConnectPanel`: `--url`, панель адреса (F2, `user://connect.cfg`), кнопка «Игра на этом ПК…» |
| `scripts/local_mode.gd` | автозагрузка `LocalMode`: локальный режим — папка игры (`user://local.cfg`, `HOTA_GAME_DIR`, поиск `bridge/doctor.py`), чек-лист с подсказками (F3), диалог выбора папки, запуск моста (Windows: python; Linux: wine), `user://local_run/` (status/stop/heartbeat/журнал), остановка игры и моста при выходе |
| `scripts/terrain.gd` | уровень карты: высоты (шум, скалы-обрывы, вода ниже, русла рек), меш, поле расстояний дорог/рек (скруглённые кривые через клетки), вода, облака тумана войны; высота/пикинг |
| `shaders/terrain.gdshader` | почвы (текстуры `assets/terrain/<почва>_albedo.jpg` или процедурные), мягкое смешение клеток, обрывы с триплан. скалой, снег на уступах, дороги 3 типов, реки 4 типов, туман войны, подсветка клетки, сетка |
| `shaders/water.gdshader`, `clouds.gdshader` | вода (глубина по depth-буферу, преломление, прибой и пена у берега), облака над неразведанным |
| `scripts/objects.gd` | `assets/models/manifest.json` (ключи `def:` → `obj:t:s` → `obj:t` → заглушка), GLB во время выполнения (+LOD), клетки по маскам, цвет владельца (`PlayerColor*`), деревья/кусты MultiMesh, мелкая растительность-декор, скрытие в тумане |
| `scripts/procgen.gd`, `shaders/props.gdshader`, `foliage.gdshader`, `glow.gdshader` | процедурные заглушки по категориям: ели/дубы/сухие, горы, камни, кучи ресурсов, сундук, шахта, город по фракции, жилище, мельница, обелиск, монстр, герой на коне… |
| `scripts/defs.gd` | номера почв, класс объекта H3 → категория, цвета игроков, маски |
| `scripts/heroes.gd`, `path_view.gd` | герои (модель/заглушка, флаг, кольцо выбора, анимация по `hero_move`), стрелки пути |
| `scripts/camera_rig.gd`, `hud.gd` | камера (наклон 50°), HUD: ресурсы, дата, герои, города (+ кнопки окон игры), уровень, «Конец хода», диалоги (ok/yesno/choose/cancel), журнал, связь |
| `scripts/engine_window.gd` | окно движка поверх мира: `window_open/frame/close`, JPEG-кадр по центру с масштабом, мышь/клавиши → `window_input` (физическая клавиша → имя для DIK-кода), застывший размытый фон и выключенный 3D-проход, пока окно открыто |

Маски объектов: 12 hex-цифр = 48-битное число, бит `i = 8*row+col`, якорь (x, y) — бит 47. Модель ставится в центр
прямоугольника клеток (block ∪ visit) на высоту земли (см. `godot/assets3d/MANIFEST.md`).

## Видимая оригинальная игра (зеркало, PLAN 4.6)

С мостом `--visible` (hello `caps` с `"mirror"`) окно HotA открыто рядом, и игрок может играть в нём. Клиент
применяет то, что пришло из окна игры, не мешая игроку: `state` с `why: "external"` — как обычный state (объекты,
туман, ресурсы, герои), камера остаётся на месте; `selected` — герой, выбранный в окне игры, выбирается и в клиенте
(без перелёта камеры); `hero_move` с `external: true` анимируется без «камера ведёт героя». Диалог с `native: true`
показывается как обычно, ответ клиента мост кликает в окне игры; `event dialog_closed` с `by: "native"` закрывает
панель (ответ дан в окне игры). Начальный выбор героя после снимка — `snapshot.selected`, если это свой герой.
