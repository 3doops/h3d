# Стиль 3D-ассетов карты

Источник — референсы пользователя `godot/ref/` (смотреть все четыре). Спрайты игры в генерацию не подаются:
описание объекта пишется текстом по оригиналу (`catalog.tsv`), стиль задают только `style_refs/`.

| реф | что берём |
|---|---|
| `ref1_snow_castle_map`, `ref2_snow_necropolis_map` | карта как диорама с высоты: снег, хвоя, скальные гряды, море, мелкие объекты (кристаллы, обелиск, мельница, кучи ресурсов) читаются силуэтом и цветом |
| `ref3_necropolis_isometric` | **формат эскиза**: один объект в изометрии 3/4 на своём основании, нейтральный фон, всё видно целиком |
| `ref4_snow_castle_render` | тот же мир в рендере: тёплое низкое солнце, длинные мягкие тени, реалистичные материалы |

`style_refs/` — уменьшенные копии, которые получает Codex: `style_single_object.jpg` (ref3) и
`style_map_closeup.jpg` (фрагмент ref1 с мелкими объектами).

## Общий стиль (входит в каждый промпт, `prompts/concept.txt`)

- **Жанр:** реалистичная фэнтези-миниатюра / диорама ручной работы, высокая детализация, без мультяшности и
  без пиксель-арта.
- **Материалы:** выветренный камень с видимой кладкой, сланцевая и черепичная кровля, грубое дерево с железными
  оковками, кованое железо, мох, сухая трава; драгоценности и магия — насыщенными акцентами (красные кристаллы,
  разноцветные самоцветы, золото).
- **Палитра:** естественные, слегка приглушённые земляные тона + 1–2 насыщенных акцента на объект. Объект не
  должен сливаться ни со снегом, ни с травой.
- **Свет в эскизе:** мягкий тёплый дневной свет сверху-слева + ровная заливка; без отброшенной тени на фон,
  без свечения и контрового света (TRELLIS запекает освещение в текстуру — сильные тени потом мешают
  освещению сцены).
- **Читаемость с высоты:** крупный цельный силуэт, слегка утрированные пропорции (как у миниатюр), без тонких
  висящих деталей, частиц, дыма; всё соединено с основным объёмом.
- **Запреты:** текст, буквы, подписи, водяные знаки, рамки; посторонние объекты; люди и животные, если их нет
  в описании; флаги и знамёна (флаг владельца `PlayerColor` добавляет `fit_asset.py`); снег на объектах
  (кроме снежных вариантов деревьев/гор) — объекты стоят на любой почве.
- **Без брендов:** в промптах нет «Heroes of Might and Magic»/HotA — стиль задают картинки.

## Формат эскиза

- Квадрат 1:1, **один объект целиком**, по центру, ~10% поля со всех сторон.
- Камера: 3/4 изометрия спереди-слева (≈35–45° в сторону от фасада, ≈35° над горизонтом), без перспективных
  искажений; фасад (вход) — правая видимая грань; существа и всадники развёрнуты к правому нижнему углу
  картинки. Деревья — вид спереди под 20°.
- Фон — ровный светло-серый, без пола и горизонта.
- Основание: здания/жилища — тонкая плита утоптанной земли по прямоугольнику клеток (`{w}:{h}`); города — низкое
  скальное плато с дорогой к воротам (как `ref3`); шахты — сама скала с плоским срезом; ресурсы, предметы,
  деревья, существа, герои, лодки — без основания, плоский низ.

TRELLIS.2 восстанавливает модель по одной картинке; вид сзади модель «додумывает» — на карте его не видно.

**Куда смотрит фасад.** Калибровка на тестовом домике с разноцветными стенами (2026-10-17): TRELLIS.2 ставит
объект ровно по осям, а камеру эскиза — на одну из четырёх диагоналей (какую — меняется), левая и правая
видимые грани эскиза ложатся на две соседние стороны. Поэтому `fit_asset.py` рендерит сырую модель с четырёх
диагоналей, сравнивает с эскизом (маска + цвета на сетке 8×8), берёт лучшую камеру `c` и считает фасадом
**правую грань эскиза**: `front = c + 45°` (у объектов на основании — с округлением до 90°), затем
разворачивает фасад на +Z glTF. Поэтому в промптах камера стоит спереди-слева, а существа и всадники
«смотрят в правый нижний угол картинки». Правило срабатывает примерно в 85–90% случаев; остальное ловится
глазами по листу моделей (вид «front») и чинится строкой `turn=±90/180` в `review.tsv`.
Мелкие предметы (артефакты) TRELLIS возвращает стоящими «как на картинке» — `lay=1` кладёт высокие узкие
предметы на бок.

## Категории (`prompts/categories.json`)

| категория | что | основание | подгонка |
|---|---|---|---|
| `town` | город фракции (одна модель на село/форт/замок пока) | скальное плато, дорога к воротам | в клетки `w×h`, высота ≤ 4, 30k тр., 2048 px, флаг |
| `building` | жилища, посещаемые здания, рынки, святилища | тонкая земляная плита | в клетки, ≤ 2.6, 20k, флаг у владеемых |
| `mine` | шахты (7 + заброшенная, склады HotA) | скала, площадка у входа | в клетки, ≤ 2.2, флаг |
| `resource` | 7 ресурсов | нет | ≤ 0.72 поперёк, ≤ 0.55 в высоту |
| `pickup` | сундук, костёр, свиток, артефакт, ящик Пандоры, лампа… | нет | ≤ 0.7 |
| `tree` | одно дерево (хвоя, снежная хвоя, дуб, мёртвое, пальма…) | корневой срез | ≤ 1.05 × 1.5, 3k тр., 512 px |
| `bush` | кусты, кактусы, грибы, цветы | нет | ≤ 0.95, 4k |
| `mountain` | горные массивы разных размеров (обычные/снежные/вулканические) | плоский срез | в клетки, 10k |
| `rock` | валуны, скальные выходы | нет | в клетки, 6k |
| `landform` | кратеры, озёра, дюны, лава, ямы | тонкая плита почвы | в клетки |
| `creature` | бродячий монстр | нет | ≤ 1.1 × 1.3 (крупным `fit=max_xz=1.5`) |
| `hero` | герой верхом (по классу) | нет | ≤ 1.25 |
| `boat`, `water` | лодки, буи, обломки, водоворот, водные банки | срез по ватерлинии | ≤ 1.3 / в клетки |
| `portal` | монолиты, порталы, врата подземелья | каменная площадка | в клетки, ≤ 2 |

Подгонка `footprint`: перед модели стоит на передней кромке своих клеток, назад модель может выходить на
`back` клеток (шахты — 1, здания — 0.8, города — 0.4: в H3 картинка поднимается над занятой передней строкой,
а маска блокирует только её); по X и Z допускается неравный масштаб до 1.25×. Объекты на основании
выравниваются по осям (`align`: минимальный прямоугольник основания) и теряют «висящие» куски.

Строки `kind=clump` (леса из нескольких деревьев) не генерируются: `assemble_clump.py` расставляет готовые
модели деревьев по занятым клеткам маски DEF. `kind=skip` — объекты без вида (событие, случайные объекты,
грааль), `kind=decal` — плоские наложения почвы (магические равнины, проклятая земля и т.п.) — это текстуры,
не модели.

## Как писать описание (`description` в каталоге)

Английский, 1–3 предложения, только то, что видно: форма, части, материалы, цвета, характерные детали из
оригинального спрайта (имя объекта не помогает генератору — помогает «что нарисовано»). Без названий игры,
без механики. Пример: *A gold mine dug into a steep weathered brown-and-ochre rock outcrop with some green moss:
a timber-framed mine entrance in the front face, a small iron mine cart full of glittering gold nuggets on short
rails in front of it.*
